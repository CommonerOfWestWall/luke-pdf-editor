# 0.3.1 多文档渲染与审读键盘导航验证记录

日期：2026-07-24

## 缺陷与根因

- 打开两份 PDF 后来回切换，页面容器仍在但位图消失。根因是每个 `PdfClient` 的渲染调度器仍保留该标签上一次激活时的作用域；应用生成新的文档视图作用域后，新任务被误判为过期并取消。
- 全局快捷键只把左右方向键映射为翻页，没有根据审读列表或意见详情的上下文切换意见。
- 命令栏打印入口使用文字，和同组常用命令的图标表达不一致；标题栏版本停留在旧值。

## 修复

- `PdfClient.prepareViewActivation()` 在标签重新激活前取消并退役旧渲染作用域，让新视图任务成为当前作用域；普通切换不关闭 Worker、不丢失撤销栈。
- 审读列表使用 `↑/↓` 选择上一条或下一条；意见详情同时支持 `↑/↓/←/→`。`PageUp/PageDown` 继续翻页，文本输入和编辑控件保留原生方向键行为。
- 打印入口改用 Lucide 标准打印图标，并保留“打印预览 (Ctrl+P)”可访问名称。
- npm、Tauri 配置与 Rust crate 版本统一为 `0.3.1`。

## 自动验证

- 单元测试覆盖方向键的上下文映射、无选中项时的首尾进入和边界循环。
- Tauri WebView E2E 使用 380 页、253 条审读意见的合法样本与运行时生成的旋转/CropBox PDF：
  - 意见详情中 `ArrowDown` 由第 1 条跳到第 2 条，页码由 5 同步为 14；`ArrowUp` 返回第 1 条和第 5 页。
  - 打开第二份 PDF 后切回第一份，再切回第二份；两次都检查当前标签至少一张页面图像的 `naturalWidth > 0`。
  - 两项桌面 E2E 全部通过。

## 当前边界

- 多文档应用重启后的会话恢复尚未实现。
- 打印预览与批注侧栏已进入应用内测，系统打印对话框和不同打印机驱动仍需实机兼容验证。
- 本版本不生成对外安装包。

## 已关闭问题

- **P0：通过文件关联/命令行冷启动时 PDF 永久无响应。** Rust 已经读完文件，但 WebView2 冷启动阶段发给模块 Worker 的首条消息可能丢失。现由 Worker 完成 MuPDF/WASM 初始化后主动发送 ready，主线程收到后才传 PDF；真实 380 页样本的中文、空格路径已通过桌面启动 E2E。
- **P1：便签/文本框工具缺少可读选择状态。** 视觉类名会变化，但 `aria-pressed` 缺失，桌面 E2E 因此无法确认快捷键是否真正激活工具。现已补齐语义状态。
- **P1：桌面 E2E 对自由文本创建后的界面状态假设错误。** 创建后产品会进入详情，旧测试却仍直接查询列表，造成假失败；现先返回列表再验证批注卡。
- **P2：工作区控制尺寸过小。** 标签关闭、添加标签、命令搜索、缩放、页码和翻页等控件低于 32px；现统一提升并加入全工作区桌面 E2E 门禁。
- **P2：意见列表未虚拟化。** 现改为可变高度窗口化渲染；真实 253 条意见在列表顶部仅有 7 张卡常驻，滚动到底时常驻卡仍低于 40，方向键定位和详情返回由桌面 E2E 覆盖。
- **P2：高缩放下工具栏末端不可达。** 现于紧凑宽度收拢间距并隐藏可由 `Ctrl+K` 调出的低频主题按钮，审读意见开关保持可见；等效 200% UI 缩放 E2E 覆盖焦点轮廓、正文/意见切换和无页面级横向溢出。

## 尚未关闭

- **P2：1024px 同时打开缩略图和意见栏时正文偏窄。** 现有 900px 响应式断点会在更窄窗口自动隐藏缩略图；1024px 是否提前折叠需结合实际桌面缩放与用户偏好单独设计，不在本轮用一次截图强行改变。
- **P2：屏幕阅读器和完整 Tab 顺序仍未形成桌面实机证据。** 本轮的等效 200% UI 缩放自动化不能替代 Windows 真实显示缩放和辅助技术人工验收。
- **P3：生产构建持续出现 MuPDF 的 `node:fs` 与 `module` 浏览器 externalize 警告。** 当前构建、真实打开和 E2E 均通过，暂不将警告误判为运行故障，后续应在升级 MuPDF/Vite 时复核。

# 分批研发与质量门禁

“鲁科 PDF 编辑器完成”只表示：功能矩阵中适用于本产品的 PDF‑XChange 基线能力全部实现，并通过内部测试和跨阅读器外部兼容测试。任何单一里程碑都不得宣称完全替代。

## 每个功能批次

1. **定义范围**：在 `docs/feature-matrix.md` 选取可独立验收的一组功能，写出输入、可观察结果、性能指标和已知风险。
2. **实现与单元测试**：先覆盖坐标、命令、状态、保存或解析边界，再接 UI。
3. **内部自动测试**：TypeScript、Rust、生产前端构建和开发版桌面编译全部通过。
4. **内部实测**：用合法测试语料执行真实 PDF 打开、操作、保存、关闭、重开；记录结果和控制台错误。
5. **独立代码审查**：Critical 和 Important 问题必须在本批次关闭；Minor 进入矩阵或任务记录。
6. **兼容性外测**：批次稳定后，使用 PDF‑XChange、Adobe Reader、Edge 和本应用交叉打开；仅记录可复现、可合法共享的最小样本。
7. **更新状态**：只有完成对应证据后，功能矩阵才能从 🟡 改为 ✅。

## 发布与打包

- 早期里程碑默认只生成开发可执行文件。产品负责人明确要求真实安装环境测试时，可以生成标明版本、未签名状态和能力边界的受控外测包，但不得把它称为稳定发布或发布候选。
- 当查看、常用批注、评论管理、兼容保存和恢复达到功能冻结，才创建发布候选分支并启用打包。
- 发布候选必须额外验证安装、升级、卸载、许可证随附、高 DPI、多显示器、无障碍、磁盘写满和异常关闭。
- 创建任何发行包前必须生成完整的 JavaScript、Rust、MuPDF/WASM 依赖许可证清单，并人工核对许可证正文和归属信息；当前简表不能作为发行清单。
- 外测缺陷回流到功能批次，不以安装包能运行作为发布依据。

# ADR 0002：对话框授权文件会话与事务保存

- 状态：已接受
- 日期：2026-07-22

## 背景

WebView 不应凭任意路径读取或覆盖本地 PDF。普通保存还必须防止静默覆盖其他程序的修改；“另存为”失败时不得提前改变当前文档位置。Windows 替换现有文件时也需要保留原文件的安全描述符和文件属性。

## 决策

- 打开路径只能由 Rust 命令显示的原生对话框产生，随后注册为随机文档会话。
- 普通保存仅接受文档会话令牌和原始 PDF 字节。Windows 原子替换时同时生成被替换版本的备份，再将其 BLAKE3 指纹与打开或上次保存后的指纹比较；若不一致，立即恢复外部版本并把本地版本保存在同目录冲突副本中。
- “另存为”由 Rust 对话框产生一次性目标令牌。写入和原子替换成功后才更新会话路径与指纹。
- 另存为目标令牌同时记录用户确认时的存在状态与指纹：已有目标使用备份/冲突恢复；当时不存在的目标使用原子“不覆盖创建”，若随后被其他程序创建则拒绝覆盖。
- Windows 对现有目标使用 `ReplaceFileW`，对新目标使用请求写穿透的 `MoveFileExW`。`ReplaceFileW` 的写穿透标志在 Windows 中不受支持，因此耐久性保证来自替换前对临时文件执行的 `sync_all`；其他平台使用同目录重命名。
- 任意写入都先验证 PDF 文件头，在目标目录创建临时文件、刷新并同步后再替换。
- 若替换后的冲突检查、冲突副本创建或恢复步骤失败，错误必须报告仍可恢复的备份/候选文件名；不能退化为不说明恢复位置的普通 I/O 错误。最终指纹校验完成前不删除原版本备份。
- 最终目标文件指纹必须与本次导出字节的指纹一致；若替换后又被改写，保存返回失败，同时保留原版本备份并另写本地修改冲突副本。

## 后果

- WebView 无法把自行构造的路径提升为文件访问授权。
- 文件被外部程序修改时，保存会失败并保留外部版本与本地冲突副本，不存在“检查后、替换前”的静默覆盖窗口。
- 计算完整文件指纹会增加一次顺序读取成本；后续可以在不削弱冲突检测的前提下加入元数据快速路径。
- 原生打开、另存为、外部冲突和权限属性仍需在 Windows 发布验收机执行端到端测试。

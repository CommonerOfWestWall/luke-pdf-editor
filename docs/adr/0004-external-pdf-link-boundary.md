# ADR 0004：PDF 外部链接双重协议边界

- 状态：已接受
- 日期：2026-07-22

## 背景

PDF 内的 URI 属于不可信输入。浏览器模式直接调用 `window.open`，或桌面端不加限制地交给系统，都可能执行 `javascript:`、打开本地 `file:` 资源或触发危险协议。用户仍需要可靠打开正常网页与邮件链接。

## 决策

- 内部页面链接只在应用内导航，不离开应用。
- 外部链接在 React 边界先解析并只允许 `http:`、`https:` 和 `mailto:`；其他协议及无效 URI 在确认框之前拒绝。
- 通过第一层校验后仍必须显示目标 URI，并由用户明确确认。
- Tauri Rust 命令再次执行同一协议白名单、长度和控制字符校验，防止绕过前端调用原生命令。
- Windows 使用 `ShellExecuteW` 交给默认应用，不拼接或执行 shell 命令。浏览器开发模式沿用前端白名单，并使用 `noopener,noreferrer`。
- PDF JavaScript 保持禁用。

## 后果

- `javascript:`、`data:`、`file:` 和自定义协议不可由 PDF 触发。
- 新增协议必须同时修改前端与 Rust 校验、测试及本 ADR，而不能只放宽一侧。

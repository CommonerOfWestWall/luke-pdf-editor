# PDF-XChange 完整替代产品工程

**产品目标：** 对 PDF-XChange Editor V11 中适用于离线 Windows 桌面应用的能力逐项建立可追溯基线，只有全部目标项通过自动化、真实文档往返和跨阅读器验证后，才能声明“完全替代”。

## 当前最高优先级：鲁科 Look 伴生工作站

通用 PDF-XChange 追平路线不取消，但在鲁科 Look 审读产物的查看与复核流程达到门禁前，不新增与该主线无关的大型模块。当前门禁包括：

- 能识别并结构化展示鲁科 Look 写入的标准 PDF 批注，解析失败时安全回退。
- 在长文档数百条意见中完成筛选、定位、上一条/下一条和页签/PDF 页码辨识。
- 用户可以先看到问题片段、修改建议、依据与提示，原始批注属性编辑不抢占首屏。
- 真实产物内测、自动检查和桌面回归均无数据丢失；接受/拒绝等状态必须先定义标准写回协议。

达到上述门禁后，再按下方工作分解继续扩展页面组织、表单、OCR、内容编辑等通用能力。

## 完成定义

- 每项能力必须在功能矩阵中有唯一条目、明确状态、验收样本和验证记录。
- “已完成”必须同时满足：实现、自动检查、真实文档内测、PDF 往返、兼容性验证、可恢复失败处理、用户文档。
- 不复制 PDF-XChange 的代码、商标、图标、文案或像素级界面；只复现可观察的工作流与标准 PDF 行为。
- 首发范围是 Windows 10/11 x64、完全离线、本地文档；在线服务与企业云连接器单独评估，不阻塞本地替代目标。
- 开发阶段不对外打包。每个里程碑先过内部门禁，再进入真实用户外测；发布门禁通过后才生成 MSI 与便携版。

## 产品工作分解

| 工作流 | 目标能力 | 依赖 | 验收主线 |
|---|---|---|---|
| A. 文档查看与导航 | 多标签、会话恢复、连续/单页/双页、目录、缩略图、附件、图层、搜索、链接、全屏、高 DPI | PDF 内核、虚拟渲染 | 200/1000 页性能、密码/损坏/扫描样本 |
| B. 批注与审阅 | 全部常用批注、评论列表、回复/状态、样式默认、导入导出、汇总、扁平化、比较 | 坐标、命令日志、appearance stream | PDF-XChange/Adobe/Edge/本应用交叉往返 |
| C. 页面与文档组织 | 插入、删除、提取、替换、重排、裁剪、旋转、拆分、合并、页码、页眉页脚、水印、书签 | 安全保存、页面对象操作 | 页树、引用、附件、书签不丢失 |
| D. 表单 | AcroForm 填写、计算、导入导出、创建和字段属性 | 表单 appearance、JavaScript 安全策略 | Adobe/PDF-XChange 表单往返 |
| E. OCR、扫描与脱敏 | 中英 OCR、可搜索层、扫描获取、永久脱敏、结果验证 | OCR 子进程、图像流水线 | 扫描件准确率、脱敏后结构检查 |
| F. 内容编辑 | 文本、字体、图像、矢量、对象变换、内容流编辑 | 原生 MuPDF 能力评估 | 不破坏字体、布局、资源引用 |
| G. 安全与签名 | 加密权限、签名验证、Windows 证书库签名、时间戳、签名失效提示 | Windows CryptoAPI、信任策略 | 证书链、增量保存、签名验证矩阵 |
| H. 转换与打印 | 打印、图像/文本/Office 导入导出、PDF/A、PDF/UA、批处理、虚拟打印机 | 外部格式引擎、打印子系统 | 标准验证器、打印机与文件输出 |
| I. 工程专业工具 | 距离/周长/面积、比例尺、测量汇总、工程图性能、文档比较 | 批注、几何、差异引擎 | 已知比例图纸和密集矢量样本 |
| J. 产品化 | 可访问性、快捷键、设置迁移、诊断、崩溃恢复、更新、安装/卸载、帮助 | 各工作流稳定接口 | WCAG/键盘、高 DPI、多显示器、升级矩阵 |

## 里程碑顺序

1. `Look-0.1` 审读查看闭环：结构化意见、长文档定位、列表/详情和连续复核。
2. `Look-0.2` 审读状态与交付闭环：与鲁科 Look 确认协议后实现采纳/拒绝/已解决写回、汇总和复核记录。
3. `0.2` 专业查看器内部基线：`0.2a/0.2b/0.2c/0.2d` 已通过；统一渲染优先级、取消、作用域隔离和诊断已完成门禁。
4. `0.3` 批注与审阅：全文批注管理 → 文本标记 → 墨迹/图形/印章 → 回复、状态、导入导出与汇总。
5. `0.4` 文件、导航与恢复：多文档、目录、附件、会话和崩溃恢复。
6. `0.5` 页面组织与基础打印。
7. `0.6` 表单填写、测量与文档比较。
8. `0.7` OCR、扫描与永久脱敏。
9. `0.8` 内容编辑、安全、签名和标准符合性。
10. `0.9` 全功能兼容性、性能、可访问性和发布加固。
11. `1.0` 只有目标功能矩阵无缺项、无数据丢失、全部发布门禁通过后才成立。

## 项目治理

- 每个里程碑单独编写实现计划、风险清单和验证报告。
- 每个批次按“测试先行 → 最小实现 → 自动检查 → 浏览器内测 → 桌面内测 → 真实 PDF 往返 → 独立审查”执行。
- 引擎、坐标、持久化、许可证或安全边界变化必须新增 ADR。
- 兼容性缺陷必须沉淀为合法最小测试样本或可重复生成脚本。
- 每次内测只修改副本；真实用户原件不得被覆盖。
